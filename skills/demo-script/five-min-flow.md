# five-min-flow — 5분 발표 흐름

## 분당 시나리오

| 시간 | 토픽 | 화면 | 핵심 메시지 |
|---|---|---|---|
| 0:00 - 1:00 | 문제 정의 | 슬라이드 1-2 | 이상 발견 지연이 만드는 현장 손실 |
| 1:00 - 1:45 | QualityLens 한 줄 소개 | 슬라이드 3 | Predict → Explain → Act 흐름 |
| 1:45 - 2:30 | P1 통합 대시보드 | Streamlit P1 | 한눈에 보는 공장 상태 |
| 2:30 - 3:15 | P2 실시간 예측 | Streamlit P2 | 단일 샘플 입력 → 이상 판정 |
| 3:15 - 3:50 | P3 원인 분석 | Streamlit P3 | SHAP으로 기여 센서 식별 |
| 3:50 - 4:20 | P4 조치 가이드 | Streamlit P4 | threshold 위반 → 권고안 |
| 4:20 - 4:45 | 평가/차별점/확장성 | 슬라이드 4-5 | MCC 기반 평가 + 운영성 |
| 4:45 - 5:00 | 마무리 | 슬라이드 6 | 한 문장 요약 + 질문 받기 |

## 첫 60초 스크립트 (외워두기)

> "제조 현장에서 가장 큰 손실은 이상을 늦게 발견하는 것입니다.
> 발견해도 원인을 모르면 조치까지 또 시간이 걸립니다.
> QualityLens는 이 세 단계를 하나의 플랫폼으로 묶었습니다.
> 공정 센서 데이터로 이상을 **예측**하고, SHAP으로 **원인을 설명**하고,
> 임계치 엔진이 **바로 실행할 조치**를 제안합니다."

## 전환 큐

- 슬라이드 → Streamlit: "이제 실제 작동하는 화면으로 보여드리겠습니다."
- Streamlit → 슬라이드: "이런 흐름이 어떻게 평가 기준에 부합하는지 정리하면..."
- 마무리: "감사합니다. 질문 받겠습니다."

## 절대 금지

- 즉흥 데모 입력 (사전 데모 샘플만)
- 모델 재학습 시연 (시간 폭주)
- 백엔드 코드 화면 노출 (청중 이해 곡선 깨짐)
