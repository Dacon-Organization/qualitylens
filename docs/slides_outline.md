## 슬라이드 1 — 문제 정의

**제목**: 제조 현장의 가장 큰 손실, 이상 발견 지연

**메시지**:
- 이상을 늦게 발견 → 생산 라인 정지 손실
- 발견해도 원인 모름 → 조치까지 추가 지연
- 라벨링·재현·운영성 모두 부족한 기존 솔루션

**시각화**: 손실 그래프 (시간축, 손실 누적)

---

## 슬라이드 2 — 기존 접근의 한계

**제목**: 예측 모델만으로는 부족합니다

**메시지**:
- 정확도가 높아도 "왜 이상인지"를 모르면 조치 불가
- 운영자는 모델 출력이 아니라 행동이 필요
- 신뢰·재현·확장 가능한 운영형 플랫폼이 필요

**시각화**: 단순 예측 모델 vs QualityLens 비교 다이어그램

---

## 슬라이드 3 — QualityLens

**제목**: Predict → Explain → Act

**메시지**:
- Predict: XGBoost로 이상 예측 (MCC 기반)
- Explain: SHAP으로 기여 센서 식별
- Act: Threshold Engine + 권고 카드

**시각화**: 3단계 아키텍처 + 데이터 흐름 화살표

---

## 슬라이드 4 — 라이브 데모 자리 (스크린샷 4장)

- P1 통합 대시보드
- P2 실시간 예측 (FAIL 샘플)
- P3 원인 분석 (SHAP)
- P4 조치 가이드 (위반 센서)

**Real Data Verified** — UCI SECOM 실데이터 1567×590으로 학습·검증 완료
(상세: docs/validation/real_vs_dummy_report.md)

사이드바 데이터 소스 배지(🟢 real / 🟡 dummy)로 시연 중 데이터 모드를 실시간 가시화

**백업 시나리오**: Streamlit 실행 실패 시 이 슬라이드만으로 시연 대체

---

## 슬라이드 5 — 평가 지표

**제목**: MCC + Threshold Engine

**메시지**:
- 불균형 6.6% fail rate에서 MCC가 가장 신뢰
- Youden's J로 최적 threshold 산출
- PASS 데이터 mean±2σ로 sensor별 정상 범위

**수치**: model_card.md 의 MCC·PR-AUC 값 (사전 학습 결과로 채우기)

---

## 슬라이드 6 — 차별점

**제목**: 운영형 MVP — 모델이 아니라 플랫폼

**메시지**:
- 예측·설명·조치를 한 화면에서
- 결정론적 데모 모드 — 안정적 시연
- Streamlit 기반 — 배포·시연 즉시 가능
